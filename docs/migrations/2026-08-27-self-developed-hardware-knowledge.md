## 证据覆盖

- 23/23 项均有 STEP、DXF 和原理图证据路径及 SHA-256。
- 精简清单引用 109 个唯一关键证据文件：23 STEP、23 DXF、23 原理图、20 说明资料、16 数据手册、2 个扩展资产和 2 个归档索引。
- 读取检查覆盖 13 份 DOCX 和 39 份 PDF；这些文档均有可提取文本层。
- 22 个配套模块均已进入 ChatCAD 机械 profile；21 个具备可调用安装孔位，微动限位开关只保留外形并要求测量孔位。
- Chat2D 与 Chat3D 共用 `placements`；前者支持自动初排、拖动和导出 3D 配置，后者生成安装柱、顶盖孔和已确认功能开口，并拒绝碰撞/越界。
- 每条机械资料保留 `physical_fit: unverified`。OpenSCAD 成功渲染仍不等于真实打印装配通过。

- 聚焦回归 41 项通过：Schema、23 项完整性/唯一性、初学者中文名称、传感器/输出/执行器代表路径、能力门、22 个机械 profile、2D→3D 同源摆放、碰撞/越界拒绝、未知孔位不生成、中文文字和既有 CAD 行为。

- Core 发布包确定性和来源目录排除 2 项通过。内容检查包包含 22 个机械 profile、统一模块索引和摆放运行时；不包含 `knowledge_sources` 或自研交接包的 STEP、DXF、PDF、DOCX。
- ChatMaker Skill bundle 构建通过，共 26 个文件，包含更新后的 ChatMaker、ChatDuino 与 ChatCAD 路由说明。
- 原始证据 109 个文件 SHA-256 全部匹配；13 份 DOCX 和 39 份 PDF 可读取并具有文本层。
- 官方离线 Core wheelhouse 的重新准备仍被仓库既有依赖锁阻断：`pyproject.toml` 已依赖 `fonttools`，`distribution/core-runtime/requirements.lock` 尚未收录。该 CI/发布基线问题不影响本轮内容包边界验证，但修复前不能宣称新的官方离线 Core ZIP 已完成发布准备。

## 项目使用时仍需确认的条件

- 项目负责人已确认这些模块过去在 Mind+ 项目中使用正常，因此 23 项均可生成证据约束下的教学指导；本次没有重新接齐硬件，不声称当前程序已编译、烧录或产生物理效果。
- 激光接收模块的供电资料冲突；三轴加速度模块的归档编号和文件名冲突。
- 四路直流电机驱动、编码器、光照、麦克风、气体、U 形槽计数和限位开关进入具体项目时，仍需确定当次实物版本、星核板引脚和有效电平。
- 串口舵机驱动可以生成识别、协议采集和接入指导；具体协议和舵机型号确定前，不生成运动命令。
- PD 供电、并线器和 USB 集线器不是普通 GPIO 模块，进入具体项目前必须测量或确认端口、电压和负载边界。

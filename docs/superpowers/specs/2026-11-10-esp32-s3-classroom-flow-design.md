## 4. 首轮开发范围

### A. 让已有独立路线真正成为默认路线

1. 总入口先确定板型及项目需求，生成完整项目，然后使用该板型的运行层检查工具。全局环境检查只报告能力，不以 Mind+ 缺失决定项目无法继续。
2. 对已有独立工具链的板型，优先复用 ChatMaker 管理的环境；缺少时，按固定来源和版本准备必要工具，再继续原项目。一次对话内不因改代码重复准备环境。
3. 清理入口、运行层返回建议与现行板型说明的相互矛盾，包括已发现的星核板和掌控板 3.0。按板型保留实际支持边界；Nano、Uno、星辰板本轮不承诺完成新的独立工具链迁移。
4. 断网、下载失败、编译错误、端口变化均停在真实失败的步骤；输出下一项必要动作。用有限重试处理已识别问题，不以反复扫描工具或重装其他软件作为通用修复。

### B. 接入微雪 ESP32-S3-Touch-LCD-2.8

1. 建立独立板卡档案、必要知识、驱动配置和本地 CLI 入口，登记到现有目录。硬件资料有来源，初始化代码基于对应版本官方示例。
2. 以 Arduino 路线作为首轮实现选择。开发时核对并固定 Arduino CLI、Arduino-ESP32、显示/触摸库、分区、Flash、PSRAM 和 USB 设置；本设计不把未经编译验证的具体版本写成已确定兼容。
3. V1 使用 CST328，V2 使用 CST3530；屏幕均为 ST7789。先核对两个官方示例包，分别记录配置。共同的编译与烧录基础可先建设；用户实板版本明确后完成对应触摸验收。另一版本只能标注到实际达到的证据阶段。
4. 优先提供两项代表案例：最小启动/屏幕诊断，以及触屏课堂计时器。计时器包含中文或明确可读的状态、开始、暂停、重置及串口启动标记；声音、网页控制、外壳和云服务留作后续扩展。
5. 工具与缓存放在 ChatMaker 管理的隔离目录；新依赖优先使用可校验的国内来源或官方来源。已有锁定版本有效时复用，不因每次运行项目重新下载安装。
6. 对厂商示例和库核对来源与许可证；不为方便而未经核对重新分发第三方二进制。第一轮交付以本地源码和验证记录为准，正式发布与知识包签名另行安排。

### C. 在真实学生路径上验收

以“电脑没有 Mind+”作为主要测试条件。按以下过程完成一次作品：

1. 学生说出效果；ChatMaker 保存完整代码和项目配置。
2. 初次准备必需工具，之后改程序复用环境。
3. 插上已确认的目标板；唯一匹配设备时自动选端口。存在多块候选板时，只询问要使用哪块。
4. 编译、烧录、复位，并读取预期启动标记。USB 复位后重新枚举时，应重新识别同一目标，不能认定原端口永远不变。
5. 引导学生检查屏幕和触摸。代码编译成功、烧录成功、串口启动和实物效果分别报告。
6. 学生修改一处界面或计时行为，再执行一轮，确认工具复用、流程不中断。

用户要求在指定开发板上“运行/下载这个作品”时，已授权该作品的常规编译和写入；板型及目标明确后不重复询问每一个软件步骤。纯讨论不触发烧录。首次处理未知出厂程序时，保留可恢复的原始固件或已核对的官方恢复路线，再进入实际写入。

## 5. 验收标准

| 场景 | 应观察到的结果 |
| --- | --- |
| 电脑无 Mind+，已有对应独立环境 | 直接使用独立环境，不建议安装 Mind+。 |
| 电脑无 Mind+，也无对应工具 | 准备该板真正需要的工具；完成后从原项目继续。 |
| 再次运行或修改同一项目 | 不重复下载已验证且有效的工具；复用既有项目配置。 |
| 无板、多个候选端口或身份未知 | 保留源码和编译证据；只询问缺少的必要信息。 |
| 微雪板版本未知 | 不猜触控驱动，不把普通 ESP32-S3 芯片识别当成载板/版本识别；不阻塞独立的公共代码工作。 |
| 微雪板实测 | 成功烧录、观察启动标记，屏幕可见、触摸开始/暂停/重置有效，断电重启后再次可运行。 |
| WorkBuddy 首装及第二次改程序 | 在有本地执行能力的真实会话中完成；记录是否仍寻找 Mind+、重复准备环境或误用旧指令。 |
| 自动检查 | 相关行为测试与必要仓库检查通过，不能只用文字匹配测试代替实际运行验证。 |

测试可以先用临时目录和模拟工具验证状态转换、缓存、错误返回与目标选择；真实编译、真实烧录和 WorkBuddy 使用分别留证。没有实体硬件或宿主实测时，只完成软件阶段，不宣称培训验收通过。

## 6. 开发者可以直接决定的事项

- 新适配器文件名、CLI 名称、板卡 ID、共用函数的具体组织方式；保留已有公开命令兼容性，不把 AVR 项目入口直接改成 S3 入口。
- 在现有接口上实现必要的连续执行，避免为了统一而一次性重构所有板卡。
- 以官方示例和实际编译结果确定库版本、屏幕方向、字体容量与 USB 参数。
- 中文字体先覆盖示例实际用字，后续再做通用字体方案。
- 基础失败信息采用普通中文，详细日志保存在项目中，供开发者排查。
- 后续实施顺序建议为：恢复本机开发检查 → 修正独立路径 → S3 基础与显示 → 对应版本触摸 → WorkBuddy 课堂复验。

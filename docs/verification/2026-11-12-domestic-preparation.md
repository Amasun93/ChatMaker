# 2026-11-12 国内下载与独立环境升级验证

交付版本：`0.2.0-beta.6`（Python 版本 `0.2.0b6`，包含 beta.5 全部运行能力）。本轮范围是 WorkBuddy 反馈中的兼容性、下载恢复、按板准备与版本确认。复测入口见 [WorkBuddy 固定版本说明](workbuddy-retest-0.2.0-beta.6.md)。

## 实现与口径

- 经典 ESP32 与微雪 S3 使用固定 Arduino CLI 1.3.1、ESP32 core 3.3.11。按已验证组合锁定版本，不随远端索引自动升级。
- 新版 CLI 的 `platforms` 清单格式可以正确识别；`latest_version` 不再被当成已安装版本。
- 每个环境只安装当前芯片 SDK、所需 Xtensa 编译器、烧录和串口工具。没有调用 `core install`，没有安装其他 ESP32 芯片 SDK、RISC-V 编译器、GDB 或 OpenOCD。
- 大组件优先使用乐鑫国内地址，文件大小与 SHA-256 固定；支持部分下载恢复、限次重试、来源切换和独立进度通道。
- 安装使用独立目录、组件清单与原子替换。有效缓存可复用；准备失败保留已完成文件和部分下载。没有改写全局 Arduino15 或要求安装 Mind+。

初次全套测试发现旧测试夹具仍固定 beta.3、旧文本断言缺少兼容入口示例；更新夹具和文档后，第一轮 674 项测试通过（1 项跳过）。审查回归修复后 679 项通过（1 项跳过）；再修复下述 CI 夹具和镜像问题，得到上表 beta.6 的最终结果。

独立审查另外发现并通过回归复现了三项边界问题，均已修复：试运行不能执行编译或上传；managed 子进程清除可覆盖配置的 `ARDUINO_*` 环境变量；库搜索目录、用户硬件目录与工具/core 版本目录必须与已登记输入一致。未登记文件会使环境检查失败，保留原文件供排查。新增回归先失败，再修复为通过；真实固定版 CLI 在注入外部目录和索引变量后，仍读取隔离目录与空额外索引。

GitHub 首轮 Windows 检查暴露了本机未启用 DOS 8.3 别名时未触发的夹具问题：测试生成的配置记录短路径，运行实现先规范化成长路径，导致断言失败。beta.6 将这些夹具与路径断言统一为真实路径。Gitee 主镜像已经同步了正确的带说明标签，但独立标签任务拿到了 checkout 临时转换的轻量标签；新增真实本地 Git 仓库回归复现冲突，恢复原始标签对象后通过。两个已发布版本保留各自标签，复测使用 beta.6。

## 真实下载和编译

对 `dl.espressif.cn` 的 ESP32 core 3.3.11 压缩包进行了实际 Range 下载：先取得 1,048,576 字节，随后共享下载器从该偏移继续，最终得到 46,900,611 字节并通过固定 SHA-256 校验。恢复阶段耗时 5.48 秒。这个数字只描述本机当次网络，不代表中国无代理网络或课堂网络速度。

受控 HTTP 测试另外覆盖：下载连接中断、再次调用时恢复、服务器忽略 Range、错误 Content-Range、损坏完整部分文件、有效缓存零请求、严格策略拦截境外重定向。

审查修复后，在同时注入外部 Arduino 数据目录、额外索引及不可连接代理的条件下，Nova 中文 OLED（77.44 秒）和 S3 V2 课堂计时器（196.88 秒）再次实际编译通过。V1/V2 的现有环境也通过了扩展后的完整依赖检查。

以上不包含 Python 引导环境，也不是解压后磁盘占用或本次实际网络接收量。本机准备复用了项目内经哈希验证的旧压缩包，因此不能据此宣称已经完成整机零环境的全量下载测试。ESP32/S3 可以共享下载缓存；解压后的环境仍按芯片隔离。

同版本缓存复测中，经典 ESP32、S3 V1 和 S3 V2 均返回 `installation_performed: false`；完整校验分别约 10.55、12.61、12.50 秒，没有重复下载或安装。

CLI、Arduino 辅助工具、U8g2 目前保留官方直连来源；`domestic-only` 遇到没有已校验缓存或组织镜像的此类组件会明确停止。本轮没有把未知第三方镜像标成可信国内来源，也没有制作新的完整离线安装包。

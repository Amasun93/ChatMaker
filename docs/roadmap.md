# ChatMaker Beta 路线图

状态基准：2026-08-26。维护者已邀请 20 多位体验者参与测试，因此项目按 Beta 管理；这表示核心体验已经能用，但仍会根据真实反馈调整，不表示所有板卡和模块都已完成实体验收。

## P0：完成精简和事实归一化

状态：已完成。

- ChatMaker 是唯一用户入口，ChatDuino、ChatWeb、ChatCAD 是内部模块。
- 基础 Skill 不再依赖 MCP 或扫描 Codex/WorkBuddy 双宿主。
- 板卡、功能、案例和证据门分别记录，README 与 Knowledge 摘要从结构化事实生成。
- GitHub `main` 是当前推荐安装来源；rc5 只保留为历史快照。

## P1：星核板独立 CLI

状态：本轮已完成 Windows x64 最小闭环。

- ChatMaker 在自己的隔离目录中准备固定 Arduino CLI、星核板核心和必需库。
- 不要求安装或启动 Mind+ 应用；Mind+ 1.8 和 2 继续作为兼容后端。
- 已用“桌面地震预警站”验证准备、编译、COM4 上传、硬复位和 115200 串口数据。
- 下一次调整重点：收集更多电脑上的首次准备、驱动和网络失败情况，再决定是否扩展 macOS/Linux。

## P2：Beta 分发与反馈闭环

状态：待开始。

- 打通 SkillHub 自动部署和更新，让 WorkBuddy 用户可直接安装最新版。
- 把 GitHub `main`、SkillHub 与本地安装版本的可见状态说清楚。
- 根据 20 多位体验者的高频问题修正安装、串口诊断和小白提示。
- rc5 不删除、不继续当作推荐入口，也不倒写它的历史验证记录。

## P3：扩展板卡与课堂案例

状态：待 P2 反馈确定优先级。

- 评估把独立工具链扩展到 Nano、Uno 和经典掌控板。
- 每块板继续分别验证编译、上传、串口、断电重启和实体功能。
- 新增模块时复用结构化证据和摘要生成机制，不手工维护多份状态。

## P4：稳定版收口

状态：待前面阶段完成。

- 固定支持矩阵、升级策略和对外版本号。
- 完成代表性课堂项目、安装更新、回滚与发布验收。
- 只有真实通过的证据门才能写入稳定版说明。

每完成一个 Phase，先根据体验者反馈更新本页的状态、下一阶段目标和验收证据，再开始下一阶段；P1/P2/P3/P4 是工作阶段，不是下载版本号。

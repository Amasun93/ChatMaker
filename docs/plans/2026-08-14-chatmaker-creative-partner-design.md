# ChatMaker 创作伙伴设计

## 产品承诺

ChatMaker 面向没有专业编程背景的老师、学生和黑客松参与者。用户负责提出想法、表达喜欢与不喜欢，并确认作品是否达到了预期。ChatMaker 负责启发创意、提供专业方案、完成技术实现和检查真实结果。

用户不需要先学会开发板型号、前端框架、程序库或编译工具。需要使用专业词时，ChatMaker 先用日常语言解释，再把专业名称放在旁边，方便用户逐渐认识。

## 整体结构

```text
ChatMaker
├─ ChatDuino   硬件、接线、固件、编译、烧录、串口
└─ ChatWeb     前端创作、课堂工具、设备界面、浏览器验证
```

ChatMaker 是总入口。它先理解用户想完成的作品，再决定调用一个模块还是两个模块。ChatDuino 和 ChatWeb 都保留创作伙伴的工作方式，不把用户当成只会提交技术参数的人。

## 自适应创作对话

### 想法已经清楚

已有信息足以决定方案时，直接复述目标、说明关键假设并开始实现。不要为了完成访谈流程重复提问。

### 只有模糊想法

每轮只问一到两个容易回答的问题。问题围绕使用对象、想改善的体验、现场材料和完成标准展开。随后给出两到三套已经筛选过的方案。

每套方案只展示四件事。

- 作品会呈现什么效果。
- 适合什么场景。
- 需要哪些主要材料。
- 哪一点可能需要用户选择。

用户仍不满意时，再提示还有更多风格、玩法和高级游乐场可以选择。不要在第一轮把完整样式库交给小白用户。

### 用户明确要求直接做

采用安全且容易修改的默认值，先生成一版。把关键假设写清楚，随后根据预览或实物效果继续调整。

## ChatDuino

ChatDuino 把硬件想法转成安全、可以检查的实物项目。

### 默认输出

接线说明只使用一个简单的 `text` 代码块。默认不生成 SVG、Fritzing 图或其他需要额外渲染的连线图。

```text
【先断电】

1. 光敏模块 VCC → Nano 5V
2. 光敏模块 GND → Nano GND
3. 光敏模块 AO → Nano A0
4. Nano D6 → 330Ω 电阻 → LED 长脚
5. LED 短脚 → Nano GND

接好以后先检查 VCC 和 GND，再插 USB。
```

用户明确要求图片时，图形接线可以作为额外交付物，不能替代文字接线。

### 第一阶段环境

第一阶段继续复用已经安装的 Mind+ 1.x 或 2.x。ChatDuino 调用 Mind+ 自带的编译器、开发板资料、程序库和烧录工具。界面是否打开不影响后台工具的使用。

独立 Arduino CLI、开发板核心、程序库缓存、驱动诊断和离线安装包属于下一阶段。届时需要先研究成熟项目，再决定复用和组合方式。

### 知识包

常用模块记录需要包含可观察的识别方法、针脚、工作电压、接口、适用板卡、可靠程序库、最小示例、常见故障和验证证据。

示例只有经过目标板卡真实编译后，才能标记为编译已验证。烧录、串口和实物效果继续单独记录。

## ChatWeb

ChatWeb 同时支持独立前端和硬件交互页面。

### 默认体验

用户先说明想实现的效果、使用对象和希望传达的感觉。ChatWeb 推荐两到三套视觉与交互方向，用户选择后再生成作品。

小白项目默认生成一个可以直接打开的 HTML 文件，CSS 和 JavaScript 放在同一文件中。项目确实需要复用资源或代码体积明显增大时，才自动拆成多文件结构。

### 能力范围

- 课堂投票、抽签、计时、反馈墙和互动展示。
- 传感器数据看板、灯光控制和设备状态页面。
- 鼠标、触摸、粒子、光影、声音和数据驱动的创意交互。
- 手机优先的本地预览和浏览器检查。

ChatWeb 可以研究 Processing、p5.js、Three.js、GSAP、Codrops 和优秀组件案例。知识包保存设计规律、适用场景和经过许可的最小示例，不机械复制网页作品。

### 渐进功能

第一层直接提供两到三套方案。第二层在用户不满意时展开更多样式。第三层高级游乐场允许用户调整布局、颜色、动画和数据，但不会默认展示给小白用户。

## 软硬件协作

ChatMaker 在两个模块开始写代码前，先定义通信约定。

```text
用户点击什么
→ ChatWeb 发送什么命令
→ ChatDuino 怎样接收
→ 硬件执行什么动作
→ 设备返回什么数据
→ 页面怎样显示成功或失败
```

ChatDuino 不负责页面审美。ChatWeb 不猜测硬件端点、数据单位或安全状态。ChatMaker 负责检查两边是否使用同一份通信约定。

## 错误处理

- 板卡、模块、电压或针脚不确定时，先帮助识别，不生成危险接线。
- 串口或开发板不唯一时，停止自动烧录并说明怎样确认。
- 用户未选择方案时，保留当前选择范围，不擅自把某一套当成最终决定。
- 页面能打开但硬件没有响应时，分别检查浏览器、通信和实物，不把其中一步成功当成全部成功。
- 高级功能缺少运行条件时，退回单文件、模拟数据或文字接线等可靠方案。

## 证据和完成判断

ChatMaker 分别记录资料核对、代码生成、真实编译、固件烧录、串口或浏览器交互和实物效果。只有用户看到实物动作，或有合适的传感器证据时，才能报告实物效果已验证。

第一阶段完成需要满足下面的条件。

- 三个 Skill 的名称、路由和创作伙伴规则一致。
- ChatDuino 默认只输出文字接线，SVG 仅在用户明确要求时出现。
- Nano 的 Mind+ 编译、烧录和已有回归测试迁移完成。
- 第一批常用模块包含可靠库文件和经过真实编译的示例。
- ChatWeb 能生成单文件课堂工具和模拟硬件界面，并在浏览器中完成主要交互检查。
- README 让非专业用户理解产品价值、使用方式、验证状态和当前限制。

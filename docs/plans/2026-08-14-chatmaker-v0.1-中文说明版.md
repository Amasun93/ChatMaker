# ChatMaker v0.1 中文说明版

这份说明写给项目发起人，也写给以后参加培训的老师。它不要求读者懂 Python、串口、Schema 或持续集成。技术细节仍保留在英文实施计划里，日常判断进度看这份就够了。

## 我们最终想做什么

ChatMaker 想解决一件很具体的事。

一个没有专业编程经验的人，可以直接在 Codex、WorkBuddy 这类 AI 环境里说出自己的想法。AI 帮他把想法变成接线说明、完整程序和可操作的网页，再调用电脑里的编译、烧录、串口和浏览器工具完成检查。

例如老师可以这样说。

> 我有一块 Nano、一个光敏模块和一颗 LED。我想让天黑以后灯自动亮起来。

ChatMaker 以后需要继续完成下面这些动作。

1. 帮老师确认手里是什么板子和模块。
2. 用小白能理解的话说明原理。
3. 给出醒目的逐线接线步骤。
4. 生成可以整段使用的程序。
5. 调用真实工具编译程序。
6. 找到正确的开发板并完成烧录。
7. 打开串口检查数据和报错。
8. 请老师确认灯是否真的亮了。

它也会覆盖原生 HTML、CSS 和 JavaScript 页面。以后可以做课堂投票器、手机控制页面，以及 ESP32 网页控制灯光和读取传感器等项目。

## 目前做到什么水平

目前完成了十个阶段中的前两个阶段。

这两个阶段主要解决项目怎么组织、不同功能放在哪里、资料怎么保存、怎样防止 AI 把没有验证的事情说成已经完成。

可以把当前状态理解成一支施工队已经完成图纸、分工、材料编号和质量检查规则。让老师直接编译、烧录和看串口的设备会在下一阶段接入。

### 已经完成的部分

项目已经有独立文件夹和 Git 版本记录。每次修改以后都能查到改了什么，也能防止重要文件被不小心覆盖。

三个 Skill 已经分开建立。

- `ChatMaker` 负责听懂用户想做什么，再把任务交给合适的模块。
- `ChatDuino` 负责 Arduino、Nano、ESP32、接线、编译、烧录和串口流程。
- `ChatWeb` 负责前端创作、课堂工具、硬件界面和浏览器检查。

这三个 Skill 已经通过格式校验。它们目前提供工作规则和任务路线，还没有接入完整的硬件执行能力。

板卡、元器件和案例已经有统一的资料格式。第一批记录包括 Arduino Uno R3、经典 Nano、ESP32 DevKit V1、一颗普通 LED 和一个闪灯案例。

项目会分开记录四件事。

1. 资料有没有核对。
2. 程序有没有真实编译。
3. 固件有没有真实烧录。
4. 实物效果有没有真实看到。

这条规则很重要。程序编译成功，只能说明代码通过了编译。它不能证明开发板已经烧录，更不能证明灯真的亮了。

项目目前有 12 项自动测试。它们会检查重复资料、错误引用、接线冲突、不存在的针脚和丢失的程序文件。12 项测试当前全部通过。

当前本地提交编号为 `1e40207`。项目还没有创建 GitHub 远端，也没有向网上推送。

### 目前还不能直接做到的部分

当前版本还不能直接交给培训老师使用。

- 原来的 Nano Mind+ 编译和烧录程序还没有迁进来。
- 这个新项目还没有真实编译 Nano 程序。
- 还没有在这个项目里完成 Nano 实机烧录。
- 还没有串口监视工具。
- Uno 和 ESP32 还没有完成实机测试。
- 还不能自动生成并检查完整网页项目。
- 还没有 Codex 和 WorkBuddy 安装器。
- 还没有发布到 GitHub。

现有板卡资料都保留为未核对状态。文件里已经放入官方资料链接，下一步仍要逐条阅读和确认，随后才能把资料状态改成已验证。

## 怎样理解当前进度

按任务数量看，现在走到第 2 阶段，总共计划 10 个阶段。

这不能简单换算成产品已经完成百分之二十。后面的硬件迁移、真实编译、烧录、串口和手机网页联动更费时间，也更依赖实物测试。

目前已经具备稳定继续开发的条件。面向老师的主要功能还没有形成可交付版本。

更直白一点说，当前成果可以防止我们以后越做越乱，也能拦住很多错误资料和错误接线。老师现在还不能只说一句话，就让这个新项目自动把程序烧进 Nano。

## 接下来先做什么

下一阶段迁移已经验证过的 Nano Mind+ 能力。

旧项目保留在原来的位置，并继续作为只读来源。迁移时会先列清单，再复制经过核对需要保留的文件，不会把旧缓存、临时文件和发布残留整包搬过来。

需要迁移的主要能力包括下面这些。

1. 检查电脑里有没有 Mind+ 1.x 或 2.x。
2. 找到 Mind+ 自带的编译工具。
3. 编译完整 Nano 程序。
4. 排除蓝牙虚拟串口。
5. 只在唯一可靠的有线开发板出现时自动烧录。
6. 处理 Nano 常见的 57600 和 115200 两种 Bootloader 速度。
7. 没有接开发板时清楚说明目前只完成了编译。
8. 迁移原有测试和六个已经验证过的案例。

这一步完成后，ChatMaker 会第一次具备可以演示的硬件能力。届时可以先用 Nano Blink 做完整验收，从生成程序开始，一直检查到开发板上的灯真实闪烁。

## 后面的完整路线

### 第 1 阶段　项目框架

已经完成。建立项目、三个 Skill、说明文档、测试和版本记录。

### 第 2 阶段　资料规则

已经完成。建立板卡、元器件、案例的统一格式和证据状态。

### 第 3 阶段　Nano 能力迁移

下一步执行。迁移 Mind+ 检测、Nano 编译、自动烧录、端口判断和原有测试。

### 第 4 阶段　Uno 和 ESP32

分别建立 Uno 和 ESP32 的真实编译、烧录和安全检查。不同 ESP32 版本必须分清，不能看到 ESP32 三个字就套用同一份接线。

### 第 5 阶段　常用元器件

加入 LED、RGB 灯、按钮、光敏、蜂鸣器、超声波、温湿度、舵机、OLED、继电器、电位器和灯带等常用器件。

每个器件都要说明怎么辨认、怎样供电、针脚是什么意思、不同板卡怎样接，以及常见错误怎么排查。

### 第 6 阶段　串口监视

让 AI 可以打开串口、读取数据、发送指令、等待指定文字，并识别不断重启、没有输出和端口被占用等问题。

### 第 7 阶段　网页开发

让老师用自然语言生成原生网页，自动打开本地预览，并检查按钮、页面状态和浏览器报错。

### 第 8 阶段　手机控制 ESP32

完成一个代表性案例。ESP32 自己建立 Wi-Fi 热点，手机连接后打开 `192.168.4.1`，通过网页控制 LED，同时读取传感器数据。

这个案例不依赖学校现场的 Wi-Fi，适合培训和黑客松演示。

### 第 9 阶段　安装到 Codex 和 WorkBuddy

提供安装工具，保留使用者原来的设置，并检查 Python、Mind+、Arduino 工具、浏览器、驱动和串口环境。

### 第 10 阶段　公开发布

完成三块开发板的实机测试、安装测试、中英文说明、演示视频、公开 GitHub 仓库和 v0.1.0 发布包。

## 你在这个项目里负责什么

你不需要先成为程序员。

你最重要的工作是提供真实使用场景，并判断做出来的东西是否适合老师和学生。

例如你可以直接告诉我。

- 培训现场通常有哪些板卡和模块。
- 老师最容易在哪一步卡住。
- 接线说明怎样写才容易看懂。
- 一个演示做到什么程度才算成功。
- 哪些功能现在必须有，哪些可以以后再做。

我负责把这些想法翻译成项目结构、程序、测试和执行工具。涉及实物效果时，我们再一起完成最后的现场确认。

## 当前一句话结论

ChatMaker 已经完成了可靠的项目框架和质量检查规则，具备继续开发的条件。面向老师的核心硬件能力还没有迁移完成。下一步需要把现有 Nano Mind+ 能力安全地搬进来，并完成第一次完整的编译、烧录和实物验收。

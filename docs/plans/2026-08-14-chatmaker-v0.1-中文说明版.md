# ChatMaker v0.1 中文说明版

这份说明写给项目发起人，也写给以后参加培训的老师。它不要求读者懂 Python、串口、Schema 或持续集成。技术细节仍保留在英文实施计划里，日常判断进度看这份就够了。

## 我们最终想做什么

ChatMaker 想解决一件很具体的事。

一个没有专业编程经验的人，可以直接在 Codex、WorkBuddy 这类 AI 环境里说出自己的想法。AI 帮他把想法变成接线说明、完整程序和可操作的网页，再调用电脑里的编译、烧录、串口和浏览器工具完成检查。

例如老师可以这样说。

> 我有一块 Nano、一个光敏模块和一颗 LED。我想让天黑以后灯自动亮起来。

ChatMaker 以后需要继续完成下面这些动作。

1. 帮老师确认手里是什么板子和模块。
2. 用小白能理解的话说明原理。
3. 给出醒目的逐线接线步骤。
4. 生成可以整段使用的程序。
5. 调用真实工具编译程序。
6. 找到正确的开发板并完成烧录。
7. 打开串口检查数据和报错。
8. 请老师确认灯是否真的亮了。

它也会覆盖原生 HTML、CSS 和 JavaScript 页面。以后可以做课堂投票器、手机控制页面，以及 ESP32 网页控制灯光和读取传感器等项目。

## 目前做到什么水平

目前已经完成前两个基础阶段，并完成了第 3 阶段的 Nano 能力迁移和真实编译验收。

这两个阶段主要解决项目怎么组织、不同功能放在哪里、资料怎么保存、怎样防止 AI 把没有验证的事情说成已经完成。

可以把当前状态理解成：施工队不但完成了图纸、分工、材料编号和质量检查规则，还已经把 Nano 的编译和安全烧录通道接进了新项目。现在这台电脑可以找到 Mind+，也能真实编译六个 Nano 案例；因为现场没有插入有线 Nano，烧录、串口和灯是否真的亮起还没有冒充成“已完成”。

### 已经完成的部分

项目已经有独立文件夹和 Git 版本记录。每次修改以后都能查到改了什么，也能防止重要文件被不小心覆盖。

三个 Skill 已经分开建立。

- `ChatMaker` 负责听懂用户想做什么，再把任务交给合适的模块。
- `ChatDuino` 负责 Arduino、Nano、ESP32、接线、编译、烧录和串口流程。
- `ChatWeb` 负责前端创作、课堂工具、硬件界面和浏览器检查。

这三个 Skill 已经通过格式校验。ChatDuino 已接入 Nano 的 Mind+ 1.x/2.x 环境发现、编译、端口判断和安全烧录流程；Uno、ESP32 和串口监视仍在后续阶段。

板卡、元器件和案例已经有统一的资料格式。当前资料库包含 3 块板卡、8 种元器件和 7 个项目配方。六个 Nano 案例都能追溯到对应模块、接线、库文件、示例程序和证据状态。

项目会分开记录四件事。

1. 资料有没有核对。
2. 程序有没有真实编译。
3. 固件有没有真实烧录。
4. 实物效果有没有真实看到。

这条规则很重要。程序编译成功，只能说明代码通过了编译。它不能证明开发板已经烧录，更不能证明灯真的亮了。

项目目前有 65 项自动测试。它们会检查资料格式、示例是否真实存在、接线冲突、Nano 环境发现、蓝牙端口排除、Bootloader 回退、自动烧录边界、可逆安装、真实 MCP 进程、发布 ZIP、ChatWeb 和小白输出格式。65 项测试当前全部通过。

公开仓库已经建立为 `Amasun93/ChatMaker`。Nano/Mind+ 迁移已经合并到公开 `main`，本地和 GitHub Actions 都通过检查。

### 目前还不能直接做到的部分

当前版本已经形成 `v0.1.0-rc1` 发布候选，可以在有人带领的教师培训中试运行，但下面这些现场证据仍然缺失。

- 还没有在这个项目里完成 Nano 实机烧录。
- 还没有串口监视工具。
- Uno 和 ESP32 还没有完成实机测试。
- Codex 和 WorkBuddy 已完成真实安装与编译烟测，但宿主重启后的界面发现仍需确认。

现有板卡资料都保留为未核对状态。文件里已经放入官方资料链接，下一步仍要逐条阅读和确认，随后才能把资料状态改成已验证。

## 怎样理解当前进度

按任务数量看，现在走到第 3 阶段，总共计划 10 个阶段。第 3 阶段的软件迁移和编译已经完成，实机烧录与实物效果仍待有线 Nano 验收。

这不能简单换算成产品已经完成百分之二十。后面的硬件迁移、真实编译、烧录、串口和手机网页联动更费时间，也更依赖实物测试。

目前已经具备可演示的 Nano 编译能力，但还不是完整的培训交付版本。

更直白一点说，老师现在可以让 ChatDuino 生成简单接线块和完整代码，系统也能真实编译；只有在电脑识别到唯一、明确的有线开发板时才会自动烧录。当前机器没有插 Nano，所以最后几步还必须等实物。

## 接下来先做什么

六个 Nano 案例已经整理成首批元器件卡和项目配方。每张卡会记录怎样辨认、使用什么库、对应哪些示例、常见故障和板卡注意点，引用的示例文件不存在时会被自动拦住。

下一步开始 ChatWeb 的第一版：小白用户描述想法后，先得到两到三套合适方案，再生成一个可以直接打开的单文件 HTML，并在本地浏览器里检查按钮、页面状态和报错。高级“游乐场”只在用户需要更多选择时出现。

当有线 Nano 可用时，再补做 Blink 的完整实机验收：烧录、串口或运行证据、断电重启和灯真实闪烁分别记录。

## 后面的完整路线

### 第 1 阶段　项目框架

已经完成。建立项目、三个 Skill、说明文档、测试和版本记录。

### 第 2 阶段　资料规则

已经完成。建立板卡、元器件、案例的统一格式和证据状态。

### 第 3 阶段　Nano 能力迁移

软件迁移和真实编译已完成。六个案例全部编译通过；实机烧录、串口和物理效果待连接有线 Nano 后验收。

### 第 4 阶段　Uno 和 ESP32

分别建立 Uno 和 ESP32 的真实编译、烧录和安全检查。不同 ESP32 版本必须分清，不能看到 ESP32 三个字就套用同一份接线。

### 第 5 阶段　常用元器件

加入 LED、RGB 灯、按钮、光敏、蜂鸣器、超声波、温湿度、舵机、OLED、继电器、电位器和灯带等常用器件。

每个器件都要说明怎么辨认、怎样供电、针脚是什么意思、不同板卡怎样接，以及常见错误怎么排查。

### 第 6 阶段　串口监视

让 AI 可以打开串口、读取数据、发送指令、等待指定文字，并识别不断重启、没有输出和端口被占用等问题。

### 第 7 阶段　网页开发

让老师用自然语言生成原生网页，自动打开本地预览，并检查按钮、页面状态和浏览器报错。

### 第 8 阶段　手机控制 ESP32

完成一个代表性案例。ESP32 自己建立 Wi-Fi 热点，手机连接后打开 `192.168.4.1`，通过网页控制 LED，同时读取传感器数据。

这个案例不依赖学校现场的 Wi-Fi，适合培训和黑客松演示。

### 第 9 阶段　安装到 Codex 和 WorkBuddy

可逆安装器、配置备份、干净目录恢复、真实用户目录安装和 Nano Blink 编译烟测已完成。Codex 和 WorkBuddy 需要重启后确认界面能发现三个 Skill。

### 第 10 阶段　公开发布

`v0.1.0-rc1` 已完成确定性 ZIP、SHA-256、中英文说明、贡献模板、一分钟演示脚本和 GitHub 预发布。Uno、ESP32 与三块板的实机矩阵不作为当前 Nano/ChatWeb 试运行候选已经完成的证据。

## 你在这个项目里负责什么

你不需要先成为程序员。

你最重要的工作是提供真实使用场景，并判断做出来的东西是否适合老师和学生。

例如你可以直接告诉我。

- 培训现场通常有哪些板卡和模块。
- 老师最容易在哪一步卡住。
- 接线说明怎样写才容易看懂。
- 一个演示做到什么程度才算成功。
- 哪些功能现在必须有，哪些可以以后再做。

我负责把这些想法翻译成项目结构、程序、测试和执行工具。涉及实物效果时，我们再一起完成最后的现场确认。

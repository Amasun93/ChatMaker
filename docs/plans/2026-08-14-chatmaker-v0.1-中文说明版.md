# ChatMaker v0.1 中文说明版

这份说明写给项目发起人，也写给以后参加培训的老师。它不要求读者懂 Python、串口、Schema 或持续集成。技术细节仍保留在英文实施计划里，日常判断进度看这份就够了。

## 我们最终想做什么

ChatMaker 想解决一件很具体的事。

一个没有专业编程经验的人，可以直接在 Codex、WorkBuddy 这类 AI 环境里说出自己的想法。AI 帮他把想法变成接线说明、完整程序和可操作的网页，再调用电脑里的编译、烧录、串口和浏览器工具完成检查。

例如老师可以这样说。

> 我有一块 Nano、一个光敏模块和一颗 LED。我想让天黑以后灯自动亮起来。

ChatMaker 以后需要继续完成下面这些动作。

1. 帮老师确认手里是什么板子和模块。
2. 用小白能理解的话说明原理。
3. 给出醒目的逐线接线步骤。
4. 生成可以整段使用的程序。
5. 调用真实工具编译程序。
6. 找到正确的开发板并完成烧录。
7. 打开串口检查数据和报错。
8. 请老师确认灯是否真的亮了。

它也会覆盖原生 HTML、CSS 和 JavaScript 页面。以后可以做课堂投票器、手机控制页面，以及 ESP32 网页控制灯光和读取传感器等项目。

## 目前做到什么水平

目前前两个基础阶段、Nano 能力迁移、Uno 独立适配器、串口工具、ChatWeb 基础能力和可逆安装已经落地。ESP32 已进入“安全适配和案例源码已具备、真实工具链与实物闭环待验证”的阶段。

这两个阶段主要解决项目怎么组织、不同功能放在哪里、资料怎么保存、怎样防止 AI 把没有验证的事情说成已经完成。

可以把当前状态理解成：施工队不但完成了图纸、分工、材料编号和质量检查规则，还已经把 Nano、Uno 的编译和安全烧录通道接进了新项目。现在这台电脑可以找到 Mind+，也能真实编译 10 个 Nano 案例和 1 个 Uno 案例；因为现场没有插入相应开发板，烧录、串口和灯是否真的亮起都没有冒充成“已完成”。

### 已经完成的部分

项目已经有独立文件夹和 Git 版本记录。每次修改以后都能查到改了什么，也能防止重要文件被不小心覆盖。

三个 Skill 已经分开建立。

- `ChatMaker` 负责听懂用户想做什么，再把任务交给合适的模块。
- `ChatDuino` 负责 Arduino、Nano、ESP32、接线、编译、烧录和串口流程。
- `ChatWeb` 负责前端创作、课堂工具、硬件界面和浏览器检查。

这三个 Skill 已经通过格式校验。ChatDuino 已接入 Nano 的完整 Mind+ 流程和独立 Uno 适配器。ESP32 已锁定 DOIT DevKit V1 + ESP-WROOM-32 的精确身份、官方 Core 3.3.11 和 FQBN，并新增安全的“编译后烧录”入口；本机尚未安装这个 Core，因此不会假装已经编译，也不会把 FireBeetle 或 mPython 冒充成目标板。

板卡、元器件和案例已经有统一的资料格式。当前资料库包含 3 块板卡、12 种元器件和 14 个项目配方。10 个 Nano 案例和 1 个 Uno 案例已经真实编译；2 个 ESP32 示例已经有安全接线、固件和测试，但仍等待精确官方 Core 才能编译。

项目会分开记录四件事。

1. 资料有没有核对。
2. 程序有没有真实编译。
3. 固件有没有真实烧录。
4. 实物效果有没有真实看到。

这条规则很重要。程序编译成功，只能说明代码通过了编译。它不能证明开发板已经烧录，更不能证明灯真的亮了。

项目目前有 126 项自动测试。它们会检查资料格式、首批 12 种模块、中文资料搜索、示例是否真实存在、接线冲突、Nano 与 Uno 环境、ESP32 精确 Core/FQBN 和载板身份、蓝牙端口排除、独立上传规则、AP 接口合同、串口会话、可逆安装、真实 MCP 进程、发布 ZIP、ChatWeb 和小白输出格式。

公开仓库已经建立为 `Amasun93/ChatMaker`。Nano/Mind+ 迁移已经合并到公开 `main`，本地和 GitHub Actions 都通过检查。

### 目前还不能直接做到的部分

`v0.1.0-rc4` 已公开发布，可以在有人带领的教师培训中试运行；公开 `main` 和当前开发分支在此基础上继续扩充，但下面这些现场证据仍然缺失。

- 还没有在这个项目里完成 Nano 实机烧录。
- Uno 已完成真实编译但没有完成实机烧录；ESP32 的精确适配和 AP 案例源码已经具备，但官方 Core、真实编译和实机测试仍未完成。
- Codex 和 WorkBuddy 的 rc4 安装已经真实刷新并核对；本轮新增的 23 工具开发版仍需在提交后再次刷新验收。

资料状态按条目分别记录。新增的 RGB 灯、电位器、5 V 继电器控制端和 WS2812B 已核对公开资料并完成代码编译；没有实物的条目仍保持烧录和物理效果未验证。

## 怎样理解当前进度

十阶段计划不是简单按顺序推进。目前仓库基础、资料格式、Nano 迁移、Uno 独立编译、首批模块、串口层、ChatWeb 和安装发布的可执行部分已经落地；ESP32、软硬件真实联动和实物效果仍待后续验证。

这不能简单换算成产品已经完成百分之二十。后面的硬件迁移、真实编译、烧录、串口和手机网页联动更费时间，也更依赖实物测试。

目前已经具备可演示的 Nano 编译、串口诊断和 ChatWeb 课堂工具能力，但硬件现场闭环还不能算完整。

更直白一点说，老师现在可以让 ChatDuino 生成简单接线块和完整代码，系统也能真实编译；只有在电脑识别到唯一、明确的有线开发板时才会自动烧录。当前机器没有插 Nano，所以最后几步还必须等实物。

## 接下来先做什么

10 个 Nano 案例、1 个 Uno 案例和 2 个 ESP32 案例已经整理到首批 12 种元器件卡和 14 个项目配方中。每张卡会记录怎样辨认、使用什么库、对应哪些示例、常见故障和板卡注意点，引用的示例文件不存在时会被自动拦住。

ChatWeb 第一版已经能先给小白两到三套方案，再生成一个可以直接打开的单文件 HTML，并在本地浏览器里检查按钮、页面状态和报错。高级“游乐场”仍只在用户需要更多选择时出现。

当有线 Nano 可用时，再补做 Blink 的完整实机验收：烧录、串口或运行证据、断电重启和灯真实闪烁分别记录。

## 后面的完整路线

### 第 1 阶段　项目框架

已经完成。建立项目、三个 Skill、说明文档、测试和版本记录。

### 第 2 阶段　资料规则

已经完成。建立板卡、元器件、案例的统一格式和证据状态。

### 第 3 阶段　Nano 能力迁移

软件迁移和真实编译已完成。10 个案例全部编译通过；实机烧录、串口和物理效果待连接有线 Nano 后验收。

### 第 4 阶段　Uno 和 ESP32

Uno 已建立独立的真实编译、端口和固定 115200 上传流程。ESP32 已建立精确身份、环境发现、编译和安全烧录入口；不同 ESP32 版本仍必须分清，不能看到 ESP32 三个字就套用同一份接线。当前缺少官方 Core 3.3.11，因此真实编译仍未验证。

### 第 5 阶段　常用元器件

加入 LED、RGB 灯、按钮、光敏、蜂鸣器、超声波、温湿度、舵机、OLED、继电器、电位器和灯带等常用器件。

每个器件都要说明怎么辨认、怎样供电、针脚是什么意思、不同板卡怎样接，以及常见错误怎么排查。

### 第 6 阶段　串口监视

已经实现打开串口、读取数据、发送指令、等待指定文字、关闭会话，以及空输出、乱码和疑似不断重启诊断。当前没有有线 Nano，因此真实运行日志仍待现场验收。

### 第 7 阶段　网页开发

基础能力已经实现：老师可以用自然语言生成原生网页，自动打开本地预览，并检查按钮、页面状态和浏览器报错。高级样式和游乐场只在需要更多选择时出现。

### 第 8 阶段　手机控制 ESP32

代表性案例的固件、手机页面、接线资料和自动合同已经具备。目标是让 ESP32 自己建立 Wi-Fi 热点，手机连接后打开 `192.168.4.1`，通过网页控制 LED，同时读取传感器数据。

这个案例不依赖学校现场的 Wi-Fi，适合培训和黑客松演示。现在还不能写成“已经跑通”：官方 Core、真实编译、烧录、手机连接、HTTP 往返、LED、电位器和断电重启都在等待后续实测。

### 第 9 阶段　安装到 Codex 和 WorkBuddy

可逆安装器、配置备份、干净目录恢复、真实用户目录安装和 Nano/Uno Blink 编译烟测已完成，三个 Skill 文件也核对一致。当前开发版 WorkBuddy 已定义 23 个工具：2 个资料、5 个 Nano、5 个 Uno、5 个 ESP32 和 6 个串口工具；本轮提交后还要再次刷新宿主并核对这个数字。

### 第 10 阶段　公开发布

`v0.1.0-rc1`、`v0.1.0-rc2`、`v0.1.0-rc3` 和 `v0.1.0-rc4` 已发布。rc4 包含独立 Uno 适配器、12 种模块、12 个配方、中文目录查询、11 个真实 AVR 编译案例和 18 个 WorkBuddy 工具。Nano、Uno、ESP32 的实机矩阵仍需现场证据，不能由发布包、编译或自动测试替代。

## 你在这个项目里负责什么

你不需要先成为程序员。

你最重要的工作是提供真实使用场景，并判断做出来的东西是否适合老师和学生。

例如你可以直接告诉我。

- 培训现场通常有哪些板卡和模块。
- 老师最容易在哪一步卡住。
- 接线说明怎样写才容易看懂。
- 一个演示做到什么程度才算成功。
- 哪些功能现在必须有，哪些可以以后再做。

我负责把这些想法翻译成项目结构、程序、测试和执行工具。涉及实物效果时，我们再一起完成最后的现场确认。

## 当前一句话结论

ChatMaker `v0.1.0-rc4` 已补齐 Nano/Uno 编译、串口运行、首批 12 种模块资料、中文目录查询、ChatWeb 单文件与本地预览、Codex/WorkBuddy 可逆安装和 SHA-256 校验；当前开发版又增加了 ESP32 安全烧录入口与 AP 手机控制案例，但 ESP32 官方 Core、真实编译和所有实物效果仍会逐项单独验收。

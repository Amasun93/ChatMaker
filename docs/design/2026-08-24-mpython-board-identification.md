# 掌控板与星核板自动识别设计

## 目标

ChatMaker 面向不熟悉硬件型号的用户。用户接入主控板后，AI 应先自动收集安全证据，尽量直接确认板卡；不能确认时，用最少的问题引导用户查看丝印，最后再请用户拍摄正反面照片，由 AI 辅助识别。

本次支持三个独立身份：经典掌控板 V2.x、掌控板 3.0、IDMC-0001 星核板 v4.2.2。星核板虽然兼容经典掌控板的软件目标，但不是掌控板实物，目录搜索、自动识别和知识路由都必须保持分离。

## 分级识别

识别结果分为 `confirmed`、`probable`、`ambiguous` 和 `unavailable`，并保存每条证据的来源。USB 串口芯片、ESP 芯片家族和单个 I2C 地址都只能作为线索，不能单独确认板卡。

1. **无损线索**：读取端口、USB VID/PID、产品字符串和序列号；必要时使用 esptool 读取 ESP 芯片家族、MAC 和 Flash 信息。esptool 会重启板卡，但不写入 Flash。
2. **现有固件自报**：先尝试读取 `CHATMAKER_BOARD_ID` 串口标记。以后由 ChatMaker 生成的程序都可以携带该标记，因此再次连接时能够直接识别。
3. **临时探针**：用户已允许自动使用临时程序。执行前必须完整备份原 Flash、记录大小和 SHA-256，并验证备份文件。只有唯一有线端口、受支持工具链、磁盘空间充足且备份成功时才能写入。探针输出结构化的芯片和板载器件证据。无论探针成功或失败，都在 `finally` 阶段尝试恢复原 Flash；恢复后再次读取并核对哈希。恢复未验证时不得报告识别完成，必须保留备份路径和小白可读的恢复提示。
4. **人工辅助**：仍为 `ambiguous` 时，先告诉用户型号通常印在板子正面或背面的哪些位置。用户无法判断时，请其拍摄清晰的正反面照片，由 AI 读取丝印和外观。

## 版本判断边界

经典掌控板 V2.0 使用 MSA300，V2.1 起改为 QMI8658C，V2.2 起更换磁传感器。探针只有在读取到经过来源核验的芯片身份证寄存器时才细分版本；否则返回 `classic-v2x` 或版本范围，不猜测具体小版本。V2.3 的部分官方差异属于 API 行为，未证明存在独立可读的硬件版本字段，因此仍可能需要背面丝印。

掌控板 3.0 使用 ESP32-S3、不同引脚、彩色 LCD、数字光线和音频硬件，不能沿用经典掌控板编译目标。星核板 v4.2.2 使用 ESP32、CH9102F 和 QMI8658，与经典掌控板存在重叠；星核板的确认需要自报标记、明确丝印或足够强的组合证据，不能从“兼容 mPython”推断。

## 小白交互

默认只展示结论和下一步，不展示 VID、PID、寄存器和命令日志。例如：

- `我找到了一块掌控板 3.0，可以继续为它生成程序。`
- `我找到的特征同时可能属于星核板和经典掌控板。请看板子正面是否印有“星核板”或“掌控板”。`
- `如果还是看不清，请拍一张正面和一张背面照片，我来帮你认。`

技术证据仍保留在结构化返回值中，供诊断和 Issue 复盘使用。

## 范围与验证

本轮增加两代掌控板的公开知识、自动识别入口、临时探针的事务保护、星核板识别说明，并修复搜索“掌控板”错误优先返回星核板的问题。不改共享安装器、账号系统或发布事务架构。

无实体板时，只能验证知识结构、分类逻辑、命令边界和模拟的备份/恢复状态机。真实的临时刷写、恢复、传感器读取和小版本识别继续标记为 `hardware-unverified`，待三种实体板分别验收。

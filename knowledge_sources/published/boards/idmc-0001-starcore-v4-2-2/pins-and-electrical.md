# 引脚选择规则

先读取 canonical board 的 `gpio_map`、`pins` 和 `code_aliases`，再分配模块。星核板丝印、Mind+ P 编号和 ESP32 GPIO 的对应关系如下：

| 丝印 / 代码 | ESP32 GPIO | 主要能力与已占用功能 |
| --- | ---: | --- |
| R / T | 3 / 1 | USB 串口 RX/TX；会影响上传和串口诊断 |
| IO37 / IO38 | 37 / 38 | 仅输入、可模拟输入；IO37 已接 QMI8658 中断 |
| P/P23、Y/P24、T/P25 | 27 / 14 / 12 | 数字、PWM、触摸；P25 是启动相关脚 |
| H/P26、O/P27、N/P28 | 13 / 15 / 4 | 数字、PWM、触摸；代码别名 `P_H/P_O/P_N`；P27/P28 启动敏感 |
| P0 / P1 | 33 / 32 | 模拟输入、数字、PWM、触摸 |
| P2 / P3 | 35 / 34 | 仅输入，可模拟输入 |
| P4 | 39 | 仅输入；`light.read()` 的软件映射，不代表板载光线传感器 |
| P5 | 0 | A 键、低电平按下、启动相关 |
| P6 | 16 | 板载无源蜂鸣器 |
| P7 | 17 | `mPython.begin()` 会按三颗 WS2812 模型初始化；实物没有板载 WS2812 |
| P8 / P9 | 26 / 25 | 数字、PWM、DAC |
| P10 | 36 | 仅输入；`sound.read()` 的软件映射，不代表板载麦克风 |
| P11 | 2 | B 键、低电平按下、启动相关 |
| P13 / P14 | 18 / 19 | 数字、PWM、SPI；已接板载 CAN TX/RX |
| P15 / P16 | 21 / 5 | 常用 UART 方案；P16 是启动相关脚 |
| P19 / P20 | 22 / 23 | 共享 I2C SCL/SDA；P20 也可作 SPI MOSI |

`P_P/P_Y/P_T/P_H/P_O/P_N` 是 `MPython` 代码别名，分别对应 P23/P24/P25/P26/P27/P28，不是另外六个 GPIO。给出接线时同时写丝印与代码名，例如“接 H/P26，代码使用 `P_H`”。

## 先排除不能随便用的脚

- P2、P3、P4、P10、IO37、IO38 只能输入，不能驱动 LED、触发脚或执行器；
- P5、P11、P16、P25、P27、P28 与启动状态有关，外设上电时强拉可能导致无法启动或上传；
- P13/P14 已连接 SIT3051TK CAN 收发器，启用 CAN 时不能再分给其他模块；
- P6 已接无源蜂鸣器，P5/P11 已接按键；
- P7 虽没有板载 WS2812，但 `mPython.begin()` 会初始化该脚；把它当普通 GPIO 前要避开这个副作用；
- R/T 是上传和调试串口，不作为新手项目的普通 GPIO 起点。

星核板有三组 3.3V 和三组 5V 的四针 I2C 接口，它们共享同一条 SCL/SDA 总线；5V 组通过板载双向电平转换连接。给学生的接线说明优先写“整体插入匹配电压的空闲 I2C 接口”，不要求逐根寻找 P19/P20；但在程序的引脚占用表中仍要保留 P19/P20，避免重复分配。

板载 QMI8658 也使用这条总线：P20/GPIO23 为 SDA，P19/GPIO22 为 SCL，地址为 `0x6B`，中断线为 GPIO37。因此它不占用一个外接插座，却必须出现在 I2C 地址占用表中；外接模块不能再使用 `0x6B`。普通体感项目不直接操作 GPIO37，也不需要重新调用 `Wire.begin()` 或另写 QMI8658 驱动。

CAN 接口使用 ESP32 控制器的 P13/GPIO18（TX）和 P14/GPIO19（RX），外部接 CAN_H/CAN_L。板载收发器不等于总线已配置完成；波特率、终端、ID 和上层协议必须与实际网络一致。没有协议或总线资料时从监听模式和只读诊断开始，不发送控制帧。

多模块项目先列引脚占用表，再检查输入输出方向、板载功能、软件初始化副作用、启动敏感端口、I2C 地址、CAN/UART 共享和电源电流。模拟传感器先输出原始值并现场校准阈值，不把一个固定阈值当成所有模块和环境的通用事实。

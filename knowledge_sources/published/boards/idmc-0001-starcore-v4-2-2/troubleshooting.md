# 按证据层级排错

先确认板型和 Mind+ 目标，再看错误发生在哪一层：找不到头文件通常是扩展未添加；找不到有线串口先检查 USB 数据线、驱动和蓝牙端口排除；启动失败检查启动敏感引脚；传感器始终为零先检查供电、S/V/G 线序、信号电平和读取节拍。

## 先排除“掌控板软件有、星核板实物没有”

- `display` 编译通过但看不到内容：先确认是否真的接了 0x3C OLED；星核板没有板载屏幕；
- `rgb.write()` 编译通过但不亮：星核板没有板载三像素 WS2812；需要外接灯并确认 P7 初始化模型是否合适；
- `light.read()` 或 `sound.read()` 出现变化：它们只是 P4/GPIO39、P10/GPIO36 的模拟读数，未外接传感器时不能解释为环境光或麦克风；
- 触摸积木没有明显触摸区：P/Y/T/H/O/N 是可触摸 GPIO 映射，不是掌控板式专用大触摸盘。

板载 A/B 键没有反应时，用 `buttonA.isPressed()` / `buttonB.isPressed()` 单独输出状态；按下应为库解释后的 `true`，底层是 P5/P11 低电平。上电或复位异常时先松开按键，并移除会强拉 P5/P11 的外设。板载蜂鸣器不响时先用 `buzz.freq(880)`、短延时和 `buzz.off()` 的最小程序；它是 P6 上的无源蜂鸣器，不要套用三线有源蜂鸣器模块接线。

板载加速度没有数值或数值不变化时，先确认代码包含 `MPython.h` 并在 `setup()` 调用了 `mPython.begin()`，然后只运行 `libraries-and-examples` 中的串口最小程序。不要让用户再接一个传感器、安装 LIS2DH12 扩展或手写 QMI8658 I2C。若外接 I2C 模块后才失效，检查是否与板载地址 `0x6B` 冲突；若数值正常但方向相反，按实际握持方向重新标定 X/Y 轴，而不是更换驱动。

如果用户要“陀螺仪”却只得到 `getX/Y/Z()`，先纠正 API 含义：当前方法是加速度 mg，不是角速度。芯片带陀螺仪不代表当前 `MPython.h` 已开放读数；应停止在驱动待验证状态。

## 供电、上传和 CAN

完全不上电时先确认使用的入口：USB-C 只接 5V，VIN 标记入口为 6-24V，另一入口为 3.8-5.5V，直接 3.3V 口只能接已稳压 3.3V。断开其他电源后一次只测试一个入口；不要用并联或回灌来“增强供电”。CH9102F 被系统识别只证明 USB 串口桥出现，不证明程序已上传或板卡已运行。

CAN 无数据时依次确认 P13/GPIO18 TX、P14/GPIO19 RX 没被其他外设占用，CAN_H/CAN_L 未接反，节点共参考、波特率一致、总线有合适终端、至少存在另一节点，并查看 CAN 控制器状态。监听模式没有帧不代表收发器损坏；发送函数返回成功也只代表入队/启动，不能证明总线确认或目标设备动作。未知工业或机器人总线禁止发送扫描、复位或控制帧。

IDMD-0001 颜色或亮度相反时，检查是否把共阳模块按低电平点亮和反相 PWM 处理；它不是 WS2812。IDMD-0002 没声音时，依次检查 5V、共地、TXD/RXD 是否交叉、存储介质和扬声器，不要只判断为串口失败。IDMD-0021 空白时先断电核对四针线序和接口电压，再用 ChatDuino OLED 参考卡里的只读扫描程序确认 0x3C/0x3D；扫不到先修接线，扫到后再核对地址、控制器和驱动。

IDMD-0021 英文正常但中文为空白或乱码时，不要换 U8g2。用 Mind+ 掌控板图形化模式上传一次只显示“你好”的最小项目，让 Mind+ 在需要时把 `Noto_Sans_CJK_SC_Light16.xbf` 写入 `0x400000`，再上传 `MPython.h` 程序。编译、应用上传、字库写入和亲眼看到中文是四个不同证据。

通用 WS2812 异常时先查 DIN/DOUT、共地、电平转换和独立 5V 容量；通用 SG90 抖动或板卡重启先查独立 5V、共地和机械卡死。IDMM-0007 协议不明时只能使用 ChatDuino 参考卡里的只读模板；没有收到主动数据是未定结论，不能用发送“试试”的方式排错。

IDMS-0001 使用普通 `INPUT`，按下是 `HIGH`；若按键抖动，做状态变化消抖。IDMS-0003 先看 P0 原始值和旋转方向。IDMS-0008 默认从 P0、3.3V 和 2500 ms 交替读取起步，P14 只用于排障对比。IDMS-0009 返回零时区分超时、接线、模块批次和 ECHO 电平，不能换成 `sen0304` I2C 路线。

七个模块示例和板载按键/蜂鸣器、QMI8658、CAN 监听代表程序当前均已编译通过。若实体运行仍异常，应从供电、接线、上传、重启、串口/CAN 和模块效果逐层补证据，不要把“可编译”写成“实物已验证”。

CAD 文件生成成功只证明几何文件已产生。加工前仍要核对孔径、公差、USB-C 开口、定位件和线束空间，并用真实 v4.2.2 板卡试装。最终报告只写已经观察到的最高状态，并列出下一项缺失验证。

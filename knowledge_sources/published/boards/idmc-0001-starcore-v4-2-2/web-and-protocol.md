# 网页和星核板协作

网页项目先定义通信合同，再分别开发 ChatWeb 和 ChatDuino：使用串口、局域网 HTTP、WebSocket 或其他传输；页面会发送什么；板卡会返回什么；断线、超时和错误怎样显示。不要先写漂亮页面，再临时猜测固件接口。

星核板的 CH9102F 可作为电脑与板卡之间的 USB 串口桥；它不等于浏览器已经获得串口权限。浏览器若使用 Web Serial，必须由用户选择端口，并显示“未连接 / 已连接 / 数据正常 / 命令已确认”的分层状态。星核板也可用 ESP32 Wi-Fi 建立局域网协议，但“热点可见”“页面打开”“HTTP/WebSocket 往返”“硬件动作”仍是四个不同证据。

板载 CAN 接口不能由普通网页直接访问。网页要读取 CAN 时，需要先定义“星核板固件作为 CAN 网关”的协议，或使用另一个明确的 USB-CAN 网关；CAN 帧、串口/网络消息和页面状态之间要有可审计映射。未知 CAN 总线先只读监听，不能让网页按钮直接发送未经确认的控制帧。

每条消息使用稳定字段和明确单位。例如传感器数据同时给出名称、数值、单位和时间；控制命令包含动作与目标状态。板卡负责硬件安全默认值，网页负责清楚显示连接状态，双方都不能把“按钮点击成功”当成执行器已经动作。

体感网页若使用板载 QMI8658，应发送已定义方向和单位的加速度数据，例如 `x_mg/y_mg/z_mg`，并提供中性姿态校准；不要把 `getX/Y/Z()` 写成陀螺仪角速度。网页预览只证明浏览器交互。固件编译只证明代码通过编译。串口或网络连接、协议往返、CAN 帧和物理效果需要分别观察并记录；缺少实板时保留为 `unverified`。

# 教师输出规范

## 1. 项目效果

先用 2-4 句日常语言说明“它会感觉到什么、什么时候行动、最后发生什么”。需要出现“传感器、阈值、编译、烧录”等专业词时，第一次出现就跟一句简单解释或生活类比。

## 2. 模块身份与材料

按“老师看得懂的名称（专业名称）+ 数量 + 已确认接线口”列出。存在多版本的模块写明本次依据。老师说不出名称时，先通过针脚数量、旁边的字母、外形和用途逐步识别；照片只能作为可选帮助，不能作为继续服务的前提。

## 3. 醒目的接线代码块

先输出标题 `## 🔌 接线说明（先断电）`，然后紧跟一个 `text` 代码块。接线说明全部放进这个代码块，不在块外另放接线表。代码块至少包含：

- `【先断电】`：第一句写“先拔掉 USB 和外部电源”。
- Mind+ 中选择 Arduino Nano ATmega328P，以及需要的模块扩展/库准备。
- `【引脚占用】`：把“引脚”顺手解释成“板子上的接线口”。
- `【按顺序接线】`：每根线按“模块上印的字母 → Nano 上印的字母”逐行书写，并给每行编号。
- LED 限流、外部电源、共地、D0/D1 等项目相关提醒。
- `【通电前检查】`：最后一句写“接好后请老师检查，再通电”。

## 4. 完整程序

输出标题 `## 💻 完整程序（可整段复制）`，然后紧跟一个 `cpp` 代码块。第二个代码块必须是完整程序，可整体交给 Mind+ Nano 编译。可调参数集中在顶部，包含调试串口和安全初始状态；注释解释“这一步让什么东西做什么”，不要只堆术语。

## 5. 执行状态

先用小白语言解释两个动作：编译是“电脑检查程序，并翻译成 Nano 能听懂的内容”；烧录是“把翻译好的程序真正装进 Nano 板”。再分别报告：

- Mind+ 环境：已发现/需下载/安装待确认。
- 编译：成功；或说明已经自动修复几次及仍存在的结构化失败原因。
- 自动上传：检测到唯一 Nano 时直接上传，不再询问老师是否同意。
- 未检测到硬件：明确写“程序已经编译好；请接入 Arduino Nano，接入 Nano 后自动上传”。老师回复已经接入后立即重试，不重复确认。
- 多串口或硬件错误：只提出当前必须由老师完成的一个动作，例如选择端口或关闭串口监视器。
- 实体效果：已观察或待老师按验收点观察。

## 6. 验收与排错

提供 3-6 个可观察点。排错只针对当前模块，按供电、共地、线序、引脚、串口/地址、库、参数的顺序。

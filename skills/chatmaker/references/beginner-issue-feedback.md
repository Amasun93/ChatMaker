# Beginner issue feedback

Use this when a beginner remains blocked after one focused troubleshooting pass, or when the evidence suggests a ChatMaker defect rather than an ordinary wiring or usage mistake.

Start with: “这可能不是你操作错了，我可以帮你把问题整理给开发者。” Do not send the user away to learn GitHub vocabulary.

Collect only what helps reproduce the problem:

- what the user wanted to make;
- what they expected to see and what actually happened;
- the exact board or project kind when relevant;
- ChatMaker version, operating system and AI host;
- the highest evidence state actually reached, such as generated, compiled, uploaded, page opened or physical effect observed;
- one short useful error excerpt and the smallest relevant generated file or screenshot.

Remove account names, home-directory names, tokens, passwords, Wi-Fi credentials, private URLs and unrelated logs. Do not gather a whole machine report when one error and one reproducer are enough.

Draft the Issue in this simple shape:

```text
标题：一句话说明哪里出问题

我想完成什么：
实际发生什么：
怎样可以再次出现：
使用环境：
已经验证到哪一步：
附件：
```

Show the finished draft to the user. Submit it publicly only after the user explicitly confirms the title, body and attachments. If direct GitHub submission is unavailable, save or copy the same text so a teacher or colleague can post it later.
